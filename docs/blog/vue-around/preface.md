# Vue 生态前言

这是 Vue 生态系列文章的序章。不乏有很多人想了解 Vue 生态的脉络是怎样的。我花了很多时间使用 Vue，也断断续续看了好几次 vue 源码。在被这些代码以及快速发展的 Vue 生态折磨太多次之后，我觉得应该好好写一篇文章说说这事儿了。我怕自己遗忘，更怕自己搞明白之后遗忘。我不期望这些文章作为什么指导手册，只希望描述得再简单一些，让更多人一读就明白，毕竟中国在这方面太烂了，最简单的中国话被用得神神叨叨，晦涩难懂，空洞无物，到头来就是误人子弟，害人不浅，没错，说的就是你，给学生们用的教材，什么玩意儿！呸！Bull Shit!

Vue 生态的核心就是 Vue 框架。这个框架完成的功能就是，定义一套数据，当数据发生变化后，使用这些数据的页面可以自动更新。框架提供了一套 API，你只要按照它的方式使用 API，就能完成刚才提到的事情。

Vue 框架有了，我需要在 vscode 里边编写代码，可是 vscode 不认识.vue 文件，不认识 vue 里的语法，于是，Vue Official 这款 vscode 出现了。

有了 Vue 框架和 vscode 编辑器，我可以写出一个前端页面了。但现实是，不能只有一个页面，需要一个 url 实现一个页面。这就是 Vue Router。它做的事情：改变 url，渲染这个 url 对应的页面。

可这些仍不够，我还想知道每个页面的组件是什么状态，每个组件的位置是在源码哪个文件哪行哪列，这样能快速找到 BUG。于是，Vue Devtools 出现了。它可以是浏览器插件，可以是独立的 App，还可以是 vite 插件。可不论采取怎样的使用形式，它的功能就只有一个：把页面里的 Vue 组件树和组件状态展示出来。

好景不长，要加入的功能越来越多，我发现很多功能使用的代码存在重复，组件使用的状态变量存在重复，我需要一个工具帮我管理，我可不想全局变量一把梭，于是，Vuex 和 Pinia 出现了。它们做的事情一样：把状态变量以及更新逻辑从组件里抽离出来，单独管理起来，如果组件需要使用，按需注入。

当然，vue 的生态还在发展中，还有一些没有提到的领域...

但趋势只有一个，那就是 vue 框架是一套底层 API，它的生态都是调用这套 API，一点点往上搭积木。

把视角放到 vue 框架身上，你会发现它是一个综合性特别强的工程。很多人工作了不少时间，但是技术上没什么进步，不是他们不努力，而是没有做对事情，如果你要做的事情，本身就是一个综合性很强的事情，你去做这个事情，一定会有很多收获。没错，**你想要有多少收获，取决于你做了什么事情**。

vue 框架至少涉及到这些内容：

1. 虚拟节点 diff 算法
2. 响应式系统
3. vue 的抽象语法树设计、解析和反解析
