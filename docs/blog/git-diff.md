# git diff 算法

使用 git 那么多年，没有想过 git 的 diff 算法，还好有 AI 技术的帮忙，让我可以在很短的时间内，获取到 diff 算法更多的信息。这要是放在以前，我都不知道该从哪里找资料了解，这些资料好不好容易理解也是个问题。

git 内置了三种算法，Myers、Patience、Histogram，默认采用 Myers 算法。下面的表格给出三者的一个比较：

|          |    Myers     |   Patience   |   Histogram    |
| :------: | :----------: | :----------: | :------------: |
|   视角   |  图上最短路  | 唯一行做锚点 |  低频行做锚点  |
| 核心工具 | BFS + 对角线 |     LIS      | 频率统计 + LIS |
|   侧重   | 编辑次数最少 |  语义更清晰  |   鲁棒性更强   |

> BFS: 广度优先搜索
> LIS: 最长递增子序列

三个算法相通之处：找到两边"相同"的部分，把它们对齐, 剩下对不齐的，左边多出来的是删除，右边多出来的是插入。

- Myers：选能让编辑次数最少的匹配方式
- Patience：选那些有唯一对应关系的行来匹配
- Histogram：选出现频率最低（最可信）的行来匹配

不理解没关系，暂时有个理解，后边会展开讲。

git diff 算法有趣之处在于，它使用了一些算法，这些算法在 leetcode 算法题目中会遇到，工作中很少碰到，如果你觉得 leetcode 题目很无聊，没什么实际用处，不妨看看本文，相信你会有所改观。

## 简化问题

git diff 做的事情，就是给出 old 代码如何通过增、删变化，变成 new 代码。

old 代码:

```js
let a = 2;
let b = 3;
let c = a + b;
```

new 代码：

```js
let a = 2;
let t = 4;
let b = 3;
let c = a + b + t;
```

多亏了 hash 算法，我们可以把代码里的每行字符串转化为整数。那么上述问题就会变成，`old:[A1, A2, A3]`, `new: [B1, B2, B3, B4]`。old 变成 new 的方式就是：

1. 删除 A2, 增加 B2
2. 删除 A3, 增加 B3
3. 增加 B4

对于 old 中要删除的行，我们用`--`标记，而 old 中要增加的行，我们用`++`标记。不难得知，`--`标记的代码，一定是 old 版本，`++`标记的代码，一定是 new 版本：

```txt
let a = 2;
-- let b = 3;
++ let t = 4;
-- let c = a + b;
++ let b = 3;
++ let c = a + b + t;
```

这是一种解法，但标记之后，并不好理解，还有更好的方式：

```txt
let a = 2;
++ let t = 4;
let b = 3;
-- let c = a + b + t;
++ let c = a + b + t;
```

所以你会发现，git diff 的问题可以简化为一个序列如何经过增加、删除、保留变成另一个序列的问题。

## Myers 算法

Myers 算法的理念很简单，按照最小编辑次数（增加、删除），找出那些操作。编辑次数最少，意味着相同的代码就很多，给出来的`--`和`++`最少、最简洁，越简洁的东西，人越容易阅读。

不妨看一下这个具体的问题，`序列x: [a, b, d, c]` 和 `序列y: [a, c, d, b]`, 每次操作只能增加或者删除一个元素，如果想将序列 x 转化成序列 y，最少的编辑次数是多少？给出具体的编辑做法？

有那个味道了吧，leetcode 算法题，哈哈哈哈。

像这种最值问题，第一个想到的就是动态规划算法。假设`d[i,j] = m`, 表示序列 x 的前 i 个元素变成序列 y 的前 j 个元素，所需要的最少编辑次数为 m 个。那么原问题的解就是`d[4, 4]`的值。接下来思考下递推公式，不难想到要根据`x[i-1]`是否等于`y[j-1]`分类讨论：

- 如果相等，则`d[i, j] = d[i-1, j - 1]`
- 如果不等，则`d[i, j] = max(d[i-1, j], d[i, j-1]) + 1`

具体计算过程就不演示了，这里给出`d[i,j]`的结果：

```txt
   j 1 2 3 4
i
1    0 1 2 3
2    1 2 3 2
3    2 3 2 3
4    3 2 3 4
```

寻找编辑做法略微不好理解，就是从`d[4,4]`倒推：

- `x[3] != y[3]`,说明`d[4,4]`来自于`d[3,4]`和`d[4,3]`的最大值，都是 3，随便取一个就可以，`d[3,4]`
- `x[2] != y[3]`,同理，取`d[2,4]`
- `x[1] == y[3]`, 说明`d[2,4]`来自于`d[1,3]`, 这次就取 `d[1,3]`
- `x[0] != y[2]`, 取`d[1,2]`
- `x[0] != y[1]`, 取`d[1,1]`
- `x[0] == y[0]`, 结束

我们依次取了`{ d[4,4], d[3,4], d[2,4], d[1,3], d[1,2], d[1,1] }`, 逆序得到 `{ d[1,1], d[1,2], d[1,3], d[2, 4], d[3,4], d[4,4]}`， 这个顺序画成有向路径：

```txt
   j 1    2    3   4
i
1    0 -> 1 -> 2   3
                 ↘
2    1    2    3   2
                   ↓
3    2    3    2   3
                   ↓
4    3    2    3   4
```

横着走一步，意味增加，比如 j 从 1 到 2 箭头，意味着增加`y[2-1]`;

竖着走一步，意味减少，比如 i 从 2 到 3 箭头，意味着减少`x[3-1]`;

对角线走，不需要编辑；

按照这个规律会有：

- `y[1]` ++
- `y[2]` ++
- `x[2]` --
- `x[3]` --

就得到：

```txt
a
b
--d
--c

a
++c
++d
b
```

问题解决了，但缺点很明显，为了创建`d[i,j]`, 你需要一个 4 _ 4 的数组。如果文件有 500 行代码，就需要 500 _ 500 的数组。要是文件有 10000 行代码。。。。而 Myers 算法精明之处，就是引入对角线的概念，引入一个 4 + 4 的数组，替换了 4 \* 4 的数组。

如果引入对角线 k = i - j, 你会发现 `[1,2]` `[2,3]` `[3,4]` 位于同一个对角线上，且 k = -1;`[1,3]` `[2,4]` 位于同一个对角线上，且 k = -2. 从 `[1,2]`横着移动到`[1,3]`, 相当于对角线 k=-1 向右（或者说向上）移动一个单位。那么，上面的箭头表述的移动，其实就可以看作对角线的移动。而且，`[1,3]`按照对角线移动到`[2,4]`，k = -2 没有变化。

上面给出的最佳路径`(1,1) (1,2) (1,3) (2,4) (3,4) (4,4)`，可以这样理解：

- (4,4)是编辑 4 次后，对角线 k=0 能够达到的最大的 j 坐标
- (3,4)是编辑 3 次后，对角线 k=-1 能够达到的最大的 j 坐标
- (2,4)是编辑 2 次后，对角线 k=-2 能够达到的最大的 j 坐标
- (1,2)是编辑 1 次后，对角线 k=-1 能够达到的最大的 j 坐标
- (1,1)是编辑 0 次后，对角线 k=-1 能够达到的最大的 j 坐标

如果用`v[k]`的一维数组存储最大的 j 坐标，你会发现有这样的递推公式：

- `v[k]=v[k+1]`: 如果对角线 K=k 是从对角线 K=k+1 向下移动一个单位
- `v[k]=v[k-1] + 1`: 如果对角线 K=k 是从对角线 K=k-1 向右移动一个单位
  到底是按照哪个方向移动过来的，取决于`v[k+1]`和`v[k-1]`谁更大。

照猫画虎，我们不禁思考，能否按照编辑次数迭代，看看从（1，1）出发，经过多少次编辑后，`v[0]=4`, 并记录沿途的`v[k]`情况。按照上边的例子，最多编辑 8 次（序列 x 全部删除，花费 4 次，序列 y 全部增加，花费 4 次）。那编辑次数就从 0 迭代到 8。编辑次数是 2 的话，需要记录所有对角线的情况么？答案是不需呀。因此初始化的时候，位于对角线 k = 0, 每次发生编辑，要么右移动，要么下移动，从 k = 0 出发，经过 4 次移动，只能到达这些对角线 k=-4,-2,0,2,4, 只需要记录这些对角线的`v[k]`情况。

这里给出 Rust 的实现：

```rust
#[derive(Debug)]
enum Edit {
    Keep(String),
    Delete(String),
    Insert(String),
}

fn myers_diff(old: &[&str], new: &[&str]) -> Vec<Edit> {
    let n = old.len() as i64;
    let m = new.len() as i64;
    let max_edits = n + m; // 最坏情况：全删再全插

    // v[k] = 对角线 k 上能走到的最远 x
    // k 范围是 -max_edits ~ +max_edits，用偏移量转成合法下标
    let offset = max_edits;
    let mut v = vec![0i64; (2 * max_edits + 1) as usize];

    // 记录每一轮（每个编辑次数 d）的 v 快照，用于后面回溯
    let mut history: Vec<Vec<i64>> = Vec::new();

    'search: for d in 0..=max_edits {
        // 本轮可达的对角线：-d, -d+2, ..., d-2, d
        let mut k = -d;
        while k <= d {
            let ki = (k + offset) as usize;

            // ── 决定这一步从哪个方向来 ──────────────────────────────
            //
            // 两个候选：
            //   从 k-1 向右走（Delete）：x = v[k-1] + 1
            //   从 k+1 向下走（Insert）：x = v[k+1]（x 不变）
            //
            // 选 x 更大的，因为 x 越大说明走得越远
            //
            // 边界情况：
            //   k == -d：左边没有 k-1，只能从 k+1 向下来（Insert）
            //   k == +d：右边没有 k+1，只能从 k-1 向右来（Delete）
            let mut x = if k == -d {
                v[ki + 1]       // 只能从上方（k+1）来，x 不变
            } else if k == d {
                v[ki - 1] + 1   // 只能从左方（k-1）来，x+1
            } else if v[ki + 1] > v[ki - 1] {
                v[ki + 1]       // 上方的 x 更大，选插入方向
            } else {
                v[ki - 1] + 1   // 左方来，x+1
            };

            // ── 沿对角线尽量滑行（Keep，免费）────────────────────────
            //
            // 只要 old[x] == new[y]，就可以斜向走，x y 同时 +1
            // 这不消耗编辑次数
            let mut y = x - k;
            while x < n && y < m && old[x as usize] == new[y as usize] {
                x += 1;
                y += 1;
            }

            v[ki] = x; // 更新这条对角线的最远 x

            if x >= n && y >= m {
                // 到达终点 (n, m)，搜索结束
                history.push(v.clone());
                break 'search;
            }

            k += 2;
        }
        history.push(v.clone()); // 保存本轮快照
    }

    // ── 回溯：从终点 (n,m) 逆向推出每一步的操作 ─────────────────
    backtrack(old, new, &history)
}

fn backtrack(old: &[&str], new: &[&str], history: &[Vec<i64>]) -> Vec<Edit> {
    let n = old.len() as i64;
    let m = new.len() as i64;
    let offset = n + m;

    let mut x = n;
    let mut y = m;
    let mut edits = Vec::new();

    // 从最后一轮往第 0 轮逆向遍历
    for (d, v) in history.iter().enumerate().rev() {
        let d = d as i64;
        let k = x - y;
        let ki = (k + offset) as usize;

        // 还原正向搜索时，这一步是从哪个方向来的
        // 逻辑和正向搜索完全镜像
        let prev_k = if k == -d {
            k + 1 // 从 k+1 来（Insert）
        } else if k == d {
            k - 1 // 从 k-1 来（Delete）
        } else if v[ki + 1] > v[ki - 1] {
            k + 1 // 上方 x 更大，Insert
        } else {
            k - 1 // 左方来，Delete
        };

        let prev_ki = (prev_k + offset) as usize;
        let prev_x = v[prev_ki];
        let prev_y = prev_x - prev_k;

        // ── 先回溯对角线部分（Keep）────────────────────────────────
        //
        // 正向时沿对角线滑行了若干步，回溯时逐步还原
        while x > prev_x && y > prev_y {
            x -= 1;
            y -= 1;
            edits.push(Edit::Keep(old[x as usize].to_string()));
        }

        // ── 再回溯这一步的编辑操作 ─────────────────────────────────
        //
        // 谁被跳过了，就对谁做操作：
        //   x 没变（从上方来）→ 跳过了 new[y] → Insert
        //   x 减少（从左方来）→ 跳过了 old[x] → Delete
        if d > 0 {
            if x == prev_x {
                // x 没变：正向时是向下走（Insert new[y]）
                y -= 1;
                edits.push(Edit::Insert(new[y as usize].to_string()));
            } else {
                // x 减少：正向时是向右走（Delete old[x]）
                x -= 1;
                edits.push(Edit::Delete(old[x as usize].to_string()));
            }
        }
    }

    edits.reverse();
    edits
}

fn print_diff(edits: &[Edit]) {
    for edit in edits {
        match edit {
            Edit::Keep(l)   => println!("  {l}"),
            Edit::Insert(l) => println!("+ {l}"),
            Edit::Delete(l) => println!("- {l}"),
        }
    }
}

fn main() {
    let old = vec!["A", "B", "C", "D"];
    let new = vec!["A", "C", "D", "E"];
    print_diff(&myers_diff(&old, &new));
}
```

## LCS（最长子序列）

上一节的动态规划算法，也可以理解为计算最长子序列的长度并给出一个序列。

假设`d[i,j]`表示序列 x 前 i 个元素和序列 y 前 j 个元素的最长子序列长度。

- 若`x[i-1] == y[j-1]`, `d[i,j] = d[i-1, j-1] + 1`
- 若`x[i-1] != y[j-1]`, `d[i,j] = max(d[i-1, j], d[i, j-1])`
  > `+1`的位置刚好和上一节的递推公式相反

`x: [a, b, d, c]`, `y: [a,k, c, d]`

```txt
        a  k  c  d
      y 1  2  3  4
   x
a  1    1  1  1  1
b  2    1  1  1  1
d  3    1  1  1  2
c  4    1  1  2  2
```

长度就是 2，然后从（4,4）倒推：

- `x[4] != y[4]`, `d[3,4] == d[4, 3]`, 随便找一个，用(4,3)
- `x[4] == y[3]`, c 就是公共子序列的一部分，转到对角线位置(3,2)
- `x[3] != y[2]`, `d[3,1] == d[2,2]`, 随便找一个，用(2,2)
- `x[2] != y[2]`, `d[2,1] == d[1,2]`, 随便找一个，用(1,2)
- `x[1] != y[2]`, 用(1,1)
- `x[1] == y[1]`, a 就是公共子序列的一部分
- 最后就得到了一个最长公共子序列`a c`

## Patience 算法

针对`序列x:[a,b,d,c]`和`序列y:[a,c,d,b]`, Myers 算法给出的处理结论是：

```txt
a
b
--d
--c

a
++c
++d
b
```

显然，这种结果可读性很差。序列 x 和序列 y 如果是你处理，一定就能看出来，只需要将序列 x 中的 b 和 c 调换一个位置就可以：

- 删除 b，增加 c
- 删除 c，增加 b

其结果：

```txt
a
--b
d
--c

a
++c
d
++b
```

可读性更好了，对不对？

Myers 算法给出的方案，依据的是最小的编辑次数，它如果尽可能多地利用不变的行，给出的结果就会是上面这个样子了。这也是 Patience 算法改进的地方，其思路很直观：**找到那些不变的行，把它们对齐，剩下的就是要变的行，属于序列 x 里的行，就删除，属于序列 y 里的行，就增加。**

Patience 算法选择要对齐的行，也有一套规则，并不是两行内容长的一样，就对齐的，它必须满足：

- 两行的内容要一样
- 这两行在各自版本中，只出现一次

```txt
a
b
c
c


a
t
b
m
c
t
c
```

这里只能选择 a 和 b 这两行对齐：

```txt
a        a
         t
b        b
c        m
c        c
         t
         c
```

不能选择 c, 因为 c 出现了 2 次。

对齐之后，剩下的处理就简单了，遍历判断：

```txt
a          a
           t++
b          b
c--        m++
c          c
           t++
           c++
```

Patience 算法的核心也出来了，就是找到用来对齐的行。这种问题有个更专业的称呼——LIS（最长递增子序列）。

`序列x:[a, b, d, c]` 和 `序列y: [t, b, a, m, c]`, 统计双方都有，且各自只出现一次的元素：

```txt
{ "a", xIndex = 0, yIndex = 2 }
{ "b", xIndex = 1, yIndex = 1 }
{ "c", xIndex = 3, yIndex = 4 }
```

你不能选择 a 和 b 做对齐，因为 a 在序列 x 中排在 b 前边，但 a 在序列 y 中排在 b 后边，会发生交叉！用作对齐的行，在各自的版本中，先后顺序也需要一致。因此，需要按照 yIndex 的值，选择一直增大的那些元素，这个就是 LIS。比如 a 和 c, b 和 c。

### 用 LCS 计算 LIS

`序列：[2, 1, 4]`的 LIS 是 `[2, 4]` 或者 `[1, 4]`。

计算 LIS 等效于 ，计算`序列x: [2, 1, 4]` 和 `序列y: [1, 2, 4]` 的 LCS。在讲 Myers 算法的时候，已经介绍过解法了，不再赘述。

### 贪心 + 二分

核心想法：维护一个"牌堆数组" tails，`tails[i]` 表示长度为 i 的递增子序列里，末尾元素的最小可能值。**末尾越小，后面能接上的数越多，越贪心。**

```txt
序列：3, 1, 4, 1, 5, 9, 2, 6
初始化 tails = []

考虑3, tails是空的，直接加入：tails[1] = 3
考虑1， 1小于等于tails[1]，替换tails[1], 则 tails[1] = 1
考虑4，4比tails[1]大，直接加入：tails[2] = 4
考虑1，1小于等于tails[1]，替换： tails[1] = 1
考虑5，5大于tails[2], 直接加入： tails[3] = 5
考虑9，9大于tails[3], 直接加入： tails[4] = 9
考虑2， 2小于等于tails[2], 替换： tails[2] = 2
考虑6，6小于等于tails[4], 替换： tails[4] = 6

最终tails=[1,2,5,6], 长度是4，则LIS的长度是4。
但是，[1,2,5,6] 并不是一个LIS序列。

获取序列的方法，是增加一个数组prev, 记录每次发生替换的时候，替换点左边元素的索引

考虑3， tails = [3], prev[0] = -1, 因为 tails[0] 左边没有数
考虑1， tails = [1], prev[1] = prev[0] = -1, 发生替换直接继承左边的值
考虑4， tails = [1, 4], prev[2] = 1, 因为 tails[2] 左边的数是 tails[1], 这个数的索引在原序列是 1
考虑1， tails = [1, 4], prev[3] = prev[1] = -1
考虑5， tails = [1, 4, 5], prev[4] = 2
考虑9， tails = [1, 4, 5, 9], prev[5] = 4
考虑2， tails = [1, 2, 5, 9], prev[6] = prev[2] = 1
考虑6， tails = [1, 2, 5, 6], prev[7] = prev[5] = 4

prev: [-1, -1, 1, -1, 2, 4, 1, 4]

从最后一个倒推，加入序列索引号是7的数， [6]
prev[7] = 4, 加入索引号是4的数，[6, 5]
prev[4] = 2, 加入索引号是2的数，[6, 5, 4]
prev[2] = 1, j爱如索引号是1的数，[6, 5, 4, 1]
prev[1] = -1, 结束。
结果翻转一下，得到LIS： [1, 4, 5, 6]
```

这个算法来自 Patience Sorting，一种分析纸牌游戏的算法，后来有人发现 LIS 与它的联系，这个算法得以问世。

这个纸牌游戏规则就是，抽一张牌，如果没有任何牌堆最顶部的数字大于等于它，就在最右侧单开一个牌堆，放上这张牌。从左到右看每个牌堆，如果发现堆顶的牌面数字大于等于它，就把这张牌放在那张牌上面。

### 应用

github 的 remote PR diff，为了提高可读性，用的就是 Patience 算法。

## Histogram

Patience 算法会在两个序列中，寻找双方都出现，在各自又出现一次的子序列，而 Histogram 的改进就是，不要求各自出现一次，而是最少次数即可。这种改进会在代码 diff 中存在大量相同的代码行时，提高 diff 效率。
